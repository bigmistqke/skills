# Canon: the Pele plugin

How the Pele plugin of the canon checker behaves, and why. It is the canon of the package `@bigmistqke/canon-plugin-pele`. It extends [the canon of the checker](../canon/CANON.md), whose terms it uses. The plugin draws the derivations of a canon as a graph: as Mermaid text, or as the SVG that [Pele](https://github.com/obsidianmd/pele) renders from that text.

## @fact pele-renders-synchronously-in-node-without-a-dom

> In Node 22.20.0 on macOS, `render` from `pele` 1.6.0 returns a plain object, not a promise, with no DOM present. For a `flowchart` text, its `svg` field is a string that starts `<svg xmlns="http://www.w3.org/2000/svg"`.

The result also carries `type`, `width`, `height` and `links`. The source, `src/core.ts` at tag `1.6.0`: `export function render(source: string | DiagramModel, options: RenderOptions = {}): RenderResult`. The API page of [pele.run](https://pele.run/api): "Use `render()` to generate SVG or `mount()` to display a diagram that adapts to its container. Both are synchronous."

Probe, run on 2026-10-19 with Node v22.20.0. A script imports `pele`, and checks that `document`, `window`, `DOMParser` and `OffscreenCanvas` are undefined before the import, and `document` and `window` after it. It renders `flowchart LR\n  A[Mermaid text] --> B[SVG]`, and printed `is a Promise: false … keys: [ 'type', 'svg', 'width', 'height', 'links' ] type: flowchart`.

## @fact pele-lays-out-a-wide-tree-tens-of-thousands-of-pixels-wide

> `pele` 1.6.0 lays out two `flowchart TD` graphs of 260 nodes and 260 edges, each labelled with five to ten hyphenated words. A binary tree with one extra edge is 44,524 pixels wide, and a random acyclic graph is 48,616 pixels wide. As a `flowchart LR`, the 159 drawn units of the checker's canon are 2,629 pixels wide.

Probe, run on 2026-10-19 with Node v22.20.0. A script builds a `flowchart TD` of 260 nodes with ids `n0` to `n259`, each labelled with five to ten hyphenated words. It joins them once as a tree with extra edges, and once as a random acyclic graph. It renders each, and prints the `width` and `height` of the result: `size=44524x832` for the tree, `size=48616x1248` for the random graph.

A second probe draws the derivations of `packages/canon/CANON.md` as a `flowchart LR`, without terms and conflicts, and renders it. It printed `2629 x 10210`.

## @fact pele-render-gives-the-same-svg-for-the-same-text

> On macOS 15.0, in Node with no `document` and no `OffscreenCanvas` global, `render` from `pele` 1.6.0 returns the same SVG string for the same text. Repeated calls, separate processes, time zones and locales change nothing, nor do Node 20.11.0, 22.13.1, 22.20.0 and 24.12.0 on arm64 and 22.20.0 on x64.
>
> On any system, with no `document` and no `OffscreenCanvas` global, rendering a `flowchart` reads no clock, random value, locale or font. It writes each number from an integer.

The source, at tag `1.6.0`:
- `src/text/measurer.ts` measures with a canvas only when `OffscreenCanvas` or `document` exists. Otherwise it measures with `metricsMeasurer`, "a table of Arial advances", and reads no font.
- `src/svg/builder.ts` writes every number as `Math.round(value * 100)`, joined as integer strings, without `toLocaleString`.
- The flowchart output carries no generated ids. The only random value and counter are in `src/mount.ts`, which `render` does not use.

Probe, run on 2026-10-19 on macOS 15.0. A script renders the graph of this repository's checker canon and hashes each SVG. It ran 50 renders in each of three processes, under four pairs of `TZ` and `LC_ALL`, and once with `Math.random` and `Date.now` replaced. It ran on Node 20.11.0, 22.13.1, 22.20.0 and 24.12.0 on arm64, and Node 22.20.0 on x64 under Rosetta 2. All 65 runs printed one sha256, `1f2242054770d390eaff83840ed1628de0bdfd8c49793ec458d9aeb00ae74748`. The probe did not run on Linux.

## @fact pele-svg-is-transparent-and-coloured-through-css-variables

> The SVG of a flowchart from `pele` 1.6.0 draws no background. Its colours come from CSS variables such as `--pele-fg`, `--pele-bg`, `--pele-line` and `--pele-surface`. Without a style, each falls back to a default: dark lines and labels, light grey nodes.

The source, `src/svg/theme.ts` at tag `1.6.0`: the root style is `--_bg:var(--pele-bg,#fff);--_fg:var(--pele-fg,#1f1f1f);…`, and shapes take the aliases, such as `fill="var(--_s)"`. Only edge labels and cluster titles use `--_bg`.

Probe, run on 2026-10-19 in Chrome 155. An SVG of two nodes, in an `<img>` on a page with background `#808080`, showed `#808080` outside and between the nodes. The node fill was `#f3f3f3`, and label and edge were `#1f1f1f`. On a `#0d1117` page, the dark background of GitHub, the edge sampled `#16181b`.

## @fact an-svg-in-an-img-takes-its-own-style-and-the-colour-scheme-of-the-img

> An SVG in an `<img>` applies its own `<style>`, and no style of the page reaches it. Its `@media (prefers-color-scheme: dark)` rules follow the `color-scheme` of the `<img>`. GitHub shows `![](file.svg)` in Markdown as such an image, with the `color-scheme` of the page's colour mode.

Sources, fetched 2026-10-19:
- The CSS Media Queries 5 draft: "Made embedded SVGs use the used color scheme of the embedding node for prefers-color-scheme".
- MDN, SVG as an image: "JavaScript is disabled. External resources … cannot be loaded."
- GitHub turns `![](./logo.svg)` into `<img src="/owner/repo/raw/main/logo.svg">`, which `raw.githubusercontent.com` serves as `image/svg+xml`.

Probes, run on 2026-10-19 in Chrome 155:
- A Pele SVG got a `<style>` as its first child, with one set of `--pele-*` colours on `svg` and another inside `@media (prefers-color-scheme: dark)`.
- In an `<img>` on a page with `color-scheme: light`, it showed the first set, and with `color-scheme: dark` the second, whatever scheme the browser emulated. A rule of the page did not reach it.
- On `github.com/BreakingLead/blockworld`, the computed `color-scheme` of the README's `<img>` followed the page's `data-color-mode`, in light, dark and auto.

## @fact pele-limits-source-output-and-edges

> `render` from `pele` 1.6.0 throws a `PeleError` with `code: 'limit'` past a limit. The limits are a source of 50,000 characters, an SVG of 4,000,000 characters, and a flowchart of 5,000 edges. The render options `limit`, `outputLimit` and `maxEdges` change these limits.

The source, `src/core.ts` at tag `1.6.0`: `const DEFAULT_LIMIT = 50000;`, `const DEFAULT_OUTPUT_LIMIT = 4_000_000;` and `const DEFAULT_MAX_EDGES = 5000;`.

Probe, run on 2026-10-19 with Node v22.20.0. A source of exactly 50,000 characters rendered, and one of 50,001 threw `code=limit`, but rendered with `{ limit: 60000 }`. With `{ outputLimit: 1000 }`, a flowchart of 260 nodes threw `code=limit`. With `{ limit: 200000 }`, a flowchart of 5,000 edges rendered, and one of 5,001 threw "Edge limit exceeded. 5000 edges found, but the limit is 5000.".
